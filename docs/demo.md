# Демо-режим для разработки

В Telegram почти всё находится за входом в аккаунт. Чтобы смотреть экраны и проверять изменения без настоящего аккаунта, в **отладочных** сборках есть выдуманный аккаунт с несколькими чатами.

```bash
adb shell am start -n org.ngram.messenger/org.telegram.messenger.DefaultIcon --ez demo true
```

Первый запуск только включает режим и закрывает приложение — запустите ещё раз той же командой или значком.

## Что это и чем не является

- Аккаунт существует только на устройстве. Никто никуда не входит.
- Пока режим включён, **к Telegram не уходит ни один запрос, требующий аккаунта**. Запросы, наполняющие главные экраны (список чатов, история, состояние обновлений, отправка сообщения), получают выдуманные ответы прямо на устройстве. Остальные отбрасываются.
- Пропускаются только запросы, не связанные с аккаунтом: языковые пакеты и настройки подключения.
- В оптимизированных (release) сборках входа в режим нет.

Выйти из режима — очистить данные приложения.

## Стекло на эмуляторе

Эмулятор считается слабым устройством, и Telegram на нём стекло не рисует. Включить все эффекты принудительно:

```bash
adb shell am start -n org.ngram.messenger/org.telegram.messenger.DefaultIcon --ez glass true
```

`--ez glass false` возвращает простой вид.

## Проверка ассистента без настоящего ключа

Поднимите на компьютере любой макет с интерфейсом OpenAI и укажите в провайдере адрес `http://10.0.2.2:<порт>/v1` — так из эмулятора виден компьютер. Адрес без `https` разрешён, потому что это локальная сеть.

## Как это сделано

`org.ngram.messenger.debug.Demo`:

- `onLaunch` — создаёт выдуманного пользователя в `UserConfig`;
- `answer` — отвечает на `messages.getDialogs`, `messages.getHistory`, `updates.getState`, `updates.getDifference`, `messages.sendMessage`;
- `harmless` — решает, какие запросы можно пропустить в сеть.

Запросы перехватываются в `NgramHost.onRequest` — это та же точка, через которую в будущем смогут работать плагины.

Две тонкости, на которых легко споткнуться:

1. Сетевой слой Telegram сам регистрирует вошедшего пользователя на сервере. Поэтому в демо-режиме `ConnectionsManager` передаёт ему нулевой идентификатор пользователя.
2. Режим должен быть включён **до первого запроса**. Одного ответа сервера «не авторизован» достаточно, чтобы приложение разлогинило выдуманный аккаунт. Отсюда и двойной запуск.
